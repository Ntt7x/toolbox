# 2026-08-26-04 · 波动率数据工程用例（调度-消息-FaaS + 增量感知）

## 背景
用户提出"市场波动率技术实现现状"思考 → 要求改造成数据工程用例（"为什么不改造为数据工程的用例，并一同进化"）→ 追问"增量数据的感知和反应"与"新增标的感知"。

## 改动
**数据工程工作流（调度器-任务-消息-FaaS 完整闭环）**：
- `core/quote.ts`：`fetchDailyOHLC`（腾讯日K OHLC，替代仅收盘价；fetchDailyCloses 复用内部 fetchDailyRows）
- `core/volatility.ts`：三口径指标（HV 主口径/分级基准 + EWMA λ=0.94 天然增量 + Parkinson 利用高低价）+ 同日替换语义（懒/调度双路径同日交替不污染窗口）+ `diffVolState` 增量感知（level 跃迁/波动突变>30%/首次）
- `core/volatilityStore.ts`：`consumeVolUpdate`（消费端幂等增量）+ `persistVolDerived`（vhist 每日序列 + vevent 事件审计）+ `enqueueVolUpdate`（新增标的感知）+ 三数据源注册（quote:v:/vhist:/vevent:）+ 懒路径统一感知
- `features/volatilityJob/`（新）：`vol-daily-update` 调度任务（每日 16:30 枚举 tradeV2 分组 + watchlist 专题标的入队 vol:update）+ `listVolWatchCodes` 聚合
- 业务接入：tradeV2 `updateGroup`（stockLimits 变化）/ watchlist `updateTopic`（新增个股）→ 立即 `enqueueVolUpdate`（不必等每日调度或懒读取）
- `core/data-infra/consumer.ts` 基建进化（用例检验出缺口）：`handlerTimeoutMs`（Promise.race 超时兜底——防 fetch 在 Windows DNS/连接阶段不响应 AbortSignal 挂起卡死消费循环）+ 周期 requeueStale（60s 扫描，运行中 processing 超 5min 自动恢复）+ staleTimer `unref()`（测试环境不阻止退出）
- 单测：volatility 20/20（三口径/同日替换/diffVolState/persistVolDerived）

## 验证
- typecheck 全绿（server+web）
- volatility 单测 20/20
- 实测：185 标的入队 → 并发 3 消费 → 184 KV 落库（三口径齐全：600519 HV 26.0%/EWMA 23.0%/Parkinson 22.5%）；调度任务 vol-daily-update 注册可见
