# 2026-09-04 · 服务配置配置化 + 配置文件化

## 背景
用户要求：把服务整体配置（SQLite 读哪个库、端口等）配置化 + 配置文件化，便于部署与服务管理。
此前这些参数散落在代码里硬编码：服务端 `PORT ?? 8787`、`db.ts` 的 DEFAULT_DATA_DIR、
`vite.config.ts` 的 8787/5173、`env.mjs` 的 `PROD_PORTS`/`DEV_SERVER_BASE` 常量、甚至
`dev.mjs` 健康检查写死 `[["server", 8787], ["web", 5173]]`（**dev 环境健康检查形同虚设的 bug**）。

## 方案
- **配置内核**：`packages/shared/config.mjs`（纯 ESM 零依赖，服务端 TS 与 scripts/*.mjs 共用同一份
  默认值与校验规则，杜绝「两份默认值各改一半」）。类型 `config.d.mts`（同名即被 TS 识别）。
- **配置文件**（仓库根）：`toolbox.config.json`（**提交**，部署基线）+ `toolbox.config.local.json`（本地私有，gitignore）。
- **优先级**：内置默认 → toolbox.config.json → toolbox.config.local.json → `TOOLBOX_CONFIG_FILE` 指定文件 → 环境变量。
- **容错**：支持注释与尾逗号（非标准 JSON，预处理剥离）；路径相对仓库根、绝对路径直接胜出；
  字段拼错/类型错/端口越界 → **启动即失败并指出来源文件**，不静默降级。
- **消费方**：服务端 `core/config.ts`（业务代码禁止直接 `process.env.*`）；脚本 `scripts/dev-utils/config.mjs` 转发。
- **新增 CLI**：`toolbox config show|paths|check|init`（部署排障第一命令，一眼看清读哪个库/哪个端口）。

## 改动文件
- 新增：`packages/shared/config.mjs`、`config.d.mts`、`toolbox.config.json`、`.gitignore` 忽略 local、scripts `config.mjs`/`config-cli.mjs`、服务端 `core/config.ts`

  配置**惰性加载**防 dev.mjs 回填时序坑）；`dev.mjs`（健康检查端口改 `ENV.serverPort/webPort`、supervisor 参数配置化）
