# 2026-09-01-01 — 自选股（原「专题自选股」）重构：标的为中心 + 分组组织 + 四功能面

**会话主题**：重构「专题自选股」。页面改名「自选股」；布局对齐仓位管理 v2（横向分组切换 + 横向功能 Tab）；
逻辑以「标的」为跟踪与管理主体；「专题」改为「分组」（基础分组 / 聚合分组）；每分组四 Tab：
行情跟踪（日/周/月）、下沉分析（财报/新闻）、提醒设置（券商式点位）、逻辑确认（入选理由与预期随时间是否成立）；
服务端以数据工程顶层观点重构数据链路；提升代码质量与工程精细度。

## 一、概念模型重构（契约驱动，先改 `packages/shared`）

| 旧（专题模型） | 新（标的 + 分组模型） | 说明 |
|---|---|---|
| `WatchlistTopic`（专题） | `WatchGroup`（分组） | `aggSources` 非空即聚合分组 |
| `WatchlistStock`（专题内个股） | `WatchItem`（标的） | 新增 `expectation` / `targetPrice` / `addedAt` |
| `topic.group`（专题分组标签） | `group.aggSources` + `legacyGroup` | 旧 `group` 归档为 `legacyGroup`，不参与展示 |
| — | `WatchPeriodStat` / `GroupPeriodPoint` | 日/周/月周期聚合 |
| — | `WatchAlertRule` / `WatchAlertHit` | 券商式提醒规则与命中 |
| — | `WatchLogicItem` / `WatchLogicReview` / `WatchLogicAnchor` | 逻辑确认（理由/预期 + 时间序列复核 + 确定性锚） |
| — | `WatchDataMeta` | 数据血缘与质量（sources / fromCache / degraded / caveats） |
| `WatchlistFundamentalResult` | `WatchFundamentalResult` | 缓存维度由「专题」改为「标的」（跨分组复用） |

**技术标识沿用 `watchlist`**（API 路径 `/tools/watchlist`、KV 前缀 `watchlist:` 不变），避免历史数据迁移风险；
业务术语与契约字段全面切换。历史数据 **读取时升级**（`store.normalizeGroup`：`stocks`→`items`、`group`→`legacyGroup`），
**零迁移脚本、零数据丢失**（实测 8 个旧专题 106 只标的全部正常升级）。

## 二、服务端：数据工程分层（源 → 采集 → 加工 → 服务）

```
源      tencent.quote（快照）· tencent.kline（日 K）· eastmoney.news（快讯）· llm.search（财报）
采集    features/watchlist/track.ts（批量取数 + 降级标注）· news.ts（新闻关联）
加工    features/watchlist/periodStats.ts（周期聚合）· alerts.ts（提醒判定）  ← 纯函数 + 单测 29 例
服务    features/watchlist/index.ts（路由 + 编排）· logic.ts（逻辑复核编排）· service.ts（财报 LLM + Chat 导入）
```

关键决策：

1. **纯函数与副作用分离**（沿用 core/volatility.ts 模式）：周期分桶、涨跌幅/振幅、等权平均、提醒判定
   全部零 I/O，单测 29 例覆盖边界（首周期无前收盘、阈值相等即命中、去重、once 停用）。
2. **`core/kline.ts` 增强而非新建**：日 K 补 OHLC 四价（原来只存 close），新增 `getDailyBars`，
   缓存结构向后兼容（旧缓存缺 OHLC 字段消费方容错）。避免"重复造第二个行情存储"。
3. **`core/stockSearch.ts` 上提**：原 features 内联裸 fetch（违反「禁止裸 fetch 散落 feature」红线）→ core 公共能力。
4. **统一缓存 `core/cache.cachedFetch`**：财报分析与提示词结果由手写 KV 改为 cachedFetch（**失败不落缓存**
   + stale-if-error 降级）；新增 `peekCache` 只读窥探（优化理由场景绝不触发取数/计费）。
5. **血缘与质量下沉前端**：`WatchDataMeta` 随数据流动，前端 `MetaBar` / `Caveats` 展示数据源、缓存、降级、缺失原因
   ——**缺失即标注**，不让用户把「无数据」误读为「数据为零」。
6. **服务端权威校验**：聚合分组不接受标的级改动、不得引用聚合分组（禁多层聚合）、提醒标的须在分组内。
7. **逻辑确认防「裁判兼运动员」假收敛**：确定性锚（基准价/入选以来涨跌幅/目标达成度/新闻条数）由服务端计算，
   LLM 只做定性判定且输入为真实采集事实（system 固定、动态内容进 user，符合 dev.md §6 成本原则）。

## 五、教训

- **`kvListRaw` 返回原始 JSON 字符串**（与 `kvGet` 不同），必须自行 `JSON.parse`——重构时直接交给 `normalizeGroup`
  导致列表接口静默返回空数组（e2e 校验才发现，已沉淀到 `domains/features.md`）。
- **等权平均序列剔除不可算周期**：首周期缺上一周期收盘时涨跌幅不可算，若保留 `count=0` 空档会被误读为「零涨幅」，
  改为直接剔除，缺失原因由各标的 `caveat` 单独标注。
- **日 K 缓存结构演进要向后兼容**：新增 OHLC 字段时旧缓存仍只有 close，消费方须容错而非假设字段存在。
