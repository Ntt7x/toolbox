# 2026-08-06 55 · LLM 用量切面重构（三层标注：业务 module 透传 + 服务端 mode + scene）

## 需求
LLM 用量切面混乱：业务 module 与底层会话 module 分离（medical-kb 问答用量记成 `knowledge.medical`）、命名风格不统一。梳理面向业务/面向服务端逻辑的划分并重构。

## 设计（dev.md §4.0 已固化）
- **module**（面向业务）：调用方透传，如 `medical-kb.ask`/`cb-rate`；命名 `<页面>.<动作>` 点分
- **mode**（面向服务端逻辑）：direct/chat-session/reasonix，底层实现固定
- **scene**（归属）：从 module 推断（it./test.→test；llm.*→system；其余 business）

## 改动
1. `chatSessionAsk(sid, msg, { signal?, module? })`：用量 module = 透传优先，缺省回落会话 module
2. `reasonixAsk(regId, text, { timeoutMs?, module? })`：同上（reg.module 兜底）
3. `knowledgeAgentAsk/Import(..., { module? })`：透传业务 module 到 reasonixAsk（缺省 knowledge.<instance>）
4. `kbAsk/kbImportFromChat(..., { module? })`：降级直调路径同样透传（缺省 knowledge.ask/import）
5. `features/rehab` medical-kb 路由：显式传 `medical-kb.ask`/`medical-kb.import`（Reasonix 路径与直调兜底一致）
6. 清理存量混乱用量数据（清空 llmUsage:log 重新积累）
7. 单测：chatSession 新增"用量归属：askOpts.module 覆盖会话 module"用例
