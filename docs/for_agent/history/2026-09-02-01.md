# 2026-09-02-01 — 引入 prod / dev 双环境：分支级端口与数据隔离 + 脚本沉淀

**会话主题**：引入 prod / dev 环境概念（prod = main 分支，dev = 各开发分支，另起端口部署与协调）；
完成当前重构分支（`refactor/watchlist-to-watchgroups`）在 dev 上的部署，并用脚本沉淀。

## 一、环境模型

| 维度 | **prod**（`main` 分支） | **dev**（其它分支） |
|---|---|---|
| 定位 | 日常使用的稳定实例，真实数据 | 分支验证实例，随便折腾 |
| server 端口 | `8787`（固定，历史约定不变） | `8800 + slot` |
| web 端口 | `5173`（固定） | `5180 + slot` |
| 数据目录 | `.file/`（真实数据） | `.file/envs/<branch-id>/data/` |
| 日志 / 状态 | `.file/` | `.file/envs/<branch-id>/{logs,dev.pids.json}` |

设计要点：

1. **槽位注册表**（`.file/envs/registry.json`）保存「分支 ↔ 槽位」映射，**稳定不变**（重启/换终端沿用同一端口）；
   首次使用自动取最小空闲槽位，上限 50。
2. **切分支即切环境**：所有脚本按当前 git 分支解析环境，无需手工改端口。
3. **数据隔离是硬保证**：dev 分支写库写到自己目录，绝不污染 prod（这是本次最核心的安全收益）。
4. **槽位可释放**：`toolbox env release [branch]`（须先 stop）；数据目录需显式 `clean-data --yes` 才删。
5. **单向数据快照**：`env sync-data` 只做 prod → dev（dev → prod 一律拒绝，防实验数据污染真实库）。
6. **自报家门**：`GET /api/health` 返回 `env` / `branch` / `dataDir`——多环境并存、端口易混淆时的第一步确认动作。

## 二、脚本沉淀（核心是 `env.mjs`）

新增 `scripts/dev-utils/env.mjs`，**一个文件同时是 CLI 和库**：

- CLI：`toolbox env status|list|start|stop|restart|sync-data|url|release [branch]|clean-data --yes`
- 库：导出 `resolveEnv / listEnvs / pidOnPort / isNodePid / branchToId / gitBranch / syncData`，
  被 `dev.mjs` / `proc.mjs` / `api.mjs` / `smoke-pages.mjs` / `browser-run.mjs` import。

改造为环境感知的既有脚本：

| 脚本 | 改造 |
|---|---|
| `dev.mjs` | 端口/状态文件/日志/数据目录取自 `resolveEnv()`；子进程注入 `childEnv()`；supervisor 经 Start-Process 独立启动不继承父 env → 环境片段以 `KEY=VALUE` 命令行参数透传 |
| `proc.mjs` | 新增 `envs` 子命令（跨环境总览）；端口按环境解析 |
| `api.mjs` | BASE 默认 `resolveEnv().urls.api`；ECONNREFUSED 时给出「先 `toolbox env start`」的可执行提示 |
| `smoke-pages.mjs` / `browser-run.mjs` | 默认打到当前分支环境的 web（可用 `SMOKE_WEB` / URL 参数覆盖） |
| `toolbox.mjs` | 新增「环境」分组 + `env` 命令注册 |

服务端 / 前端配合：

- `apps/server/src/core/db.ts`：`DATA_DIR` 由 `TOOLBOX_DATA_DIR` 覆盖（**用 `resolve` 不用 `join`**——
  join 遇绝对路径会拼成 `D:\proj\D:\env\data`）；默认仍是 `.file/`（prod 路径不变）。
- `apps/server/src/features/docs/services.ts`：`DOCS_FILE_DIR` 改由 `DATA_DIR` 解析（PDF 不再落进 prod）。
- `apps/web/vite.config.ts`：端口与 `/api` 代理目标由 `TOOLBOX_SERVER_PORT` / `TOOLBOX_WEB_PORT` 驱动；
  `strictPort: true` 不自动顺延（避免 status 显示端口与实际不符）。
- `apps/server/src/index.ts`：启动日志自报环境；`/api/health` 返回 `env` / `branch` / `dataDir`。

## 四、踩坑

1. **`env.mjs` 被 import 时会执行 CLI**：顶层直接读 `process.argv[2]`，import 方自己的参数（如 `--page`）
   会掉进 else 分支打印「用法: …」——冒烟输出里混进这段就是它。修复：加 `isMain` 闸门
   （`path.resolve(process.argv[1]) === fileURLToPath(import.meta.url)`）后才跑 CLI。
2. **`path.join` 遇绝对路径会拼接而非替换**：`join(PROJECT_ROOT, "D:\env\data")` → `D:\proj\D:\env\data`。
   dev 环境注入的正是绝对路径，必须用 `resolve(PROJECT_ROOT, raw)` 让绝对路径胜出。
3. **沙盒 `AssignProcessToJobObject: (50)`**：本会话的 bash 工具里 node 无法派生子进程
   （`dev.mjs start` 里的 `spawnSync("powershell", Start-Process ...)` 失败）。
   **这不是脚本问题**——绕法是直接用 PowerShell 的 `Start-Process` 拉起 supervisor：
   ```
   Start-Process node 'scripts/dev-utils/dev.mjs','supervise','PORT=8800','TOOLBOX_ENV=dev',
     'TOOLBOX_BRANCH=<branch>','TOOLBOX_DATA_DIR=<path>','TOOLBOX_SERVER_PORT=8800','TOOLBOX_WEB_PORT=5180'
   ```
   日常手工（真实终端）用 `toolbox env start` 即可，无此限制。
4. **prod 实例若以历史方式启动（无 env 变量）不会自报 env**：已在服务端补默认推断——
   `TOOLBOX_ENV` > `TOOLBOX_BRANCH`（main=prod / 其它=dev）> 默认 prod（不带变量启动的就是真实数据实例）。
