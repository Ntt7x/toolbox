# 2026-08-07 策略仓位管理（feat/trade-plan）合入 main

## 变更概览
新增「交易」分组第 5 个功能页面**策略仓位管理**（trade-plan）：用户预配置多个交易策略（总仓位/单日加仓上限/交易标的及各自上限%/起始持仓），在每日变动中给出日度交易计划，服务端**纯计算校验**（无 LLM）是否符合策略仓位控制，给出 error/warn/info 三级提醒。

**12 个提交（5097eb9 → ffc7ce2）经验收 fast-forward 合入 main（296f163 → ffc7ce2）**，远程/本地分支已删。

## 功能与实现
- **多策略**：KV `tradePlan:config` → `{ strategies: [{id,name,totalCapital,dailyAddLimit,stocks:[{code,name,maxWeightPct,initShares,initCost}]}] }`；策略名唯一（400）；日度计划 `tradePlan:day:<策略id>:<YYYY-MM-DD>`（日期即 id）
- **校验规则**（`compute.ts checkTradePlan`）：标的必须∈策略 / 当日加仓≤日限 / 单标的上限% / 总市值≤总仓位 / 减仓≤当前持仓 / 同 code 同日多操作→「请合并为一个交易操作」
- **前端**：策略列表+配置卡（标的行 2 行布局：代码/名称搜索补全「名称 代码」同显 + 上限% 滑块 + 起始数量/成本）+ 日度计划（总仓位×pct 滑块、重复标的下拉禁用）+ 校验结果三级告警 + 历史/日历（跨策略月历）
- **交互**：600ms debounce 自动校验（无手动按钮）；save 被 error 阻断并错误级 alert；下一交易日自动跳周一
- 单测 7 用例（合规/超日限/超上限/非法标的/减仓超持仓/重复标的/告警排序）
- `scripts/smoke-pages.mjs`（17 页 playwright 冒烟）在本分支引入，dev.md §6.4 记录

## 关键经验（dev.md §4.6）
- 类表单校验判定：用「存在有 code 的标的行」而非 `totalCapital !== undefined`（数字 0 恒非 undefined，曾致提示永不显示）
- 页面"卡加载中"根因 = mount useEffect 被重构误删（curl 测 API 测不出）→ 必须跑浏览器级冒烟
- StockCodeInput 只显示代码可读性差（备忘录反馈）→ 输入框内「名称 代码」同显，手动输入自动清 name
