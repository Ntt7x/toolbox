# 2026-08-06 43 · 公共 LLM 三种调用模式（直接 / 自研Cache会话 / Reasonix ACP）

## 需求
服务端公共 LLM 分出三种调用模式：① 直接调用（已有，经常变动需求）② 自研模仿 Reasonix 的 Cache 模式（业务特化缓存，精细成本控制）③ 调用 Reasonix Go + ACP（享受开源成果）。

## 实现
### 模式 1：直接调用（core/llm.ts，已有）
- 前缀稳定化已落地（§41）；ChatOptions 导出供复用

### 模式 2：自研 Cache 会话（core/chatSession.ts，新增）
- `createChatSession({module,system,model?,search?,json?,ttlMs?})` → KV 持久化（chatSession:<id>，TTL 30 分钟）
- `chatSessionAsk(id, userMsg)`：messages=[system,...history,user]，成功才 append；失败不动历史（保前缀）
- `compactSession`：超长保留 system + 最近 6 轮（snip），droppedTurns 统计
- `listChatSessions / deleteChatSession`
- **实测（真实 key，3 轮批量分析）**：命中率 0% → 51.0% → **88.7%**（历史累积命中增长）
- 注意：createChatSession 返回对象，ask 传 `.id`（踩坑：传对象会 key 化失败报"会话不存在"）

### 模式 3：Reasonix ACP（core/reasonix.ts，新增）
- `createReasonixSession(cwd?)`：initialize → session/new；`reasonixAsk(id, text)`：session/prompt + 收集回答；`closeReasonixSession / shutdownReasonix`
- 二进制解析：`llm.reasonixBin` 设置 → `@reasonix/cli-<platform>-<arch>` npm 包（ESM 下用 createRequire）
- **协议要点（实测踩坑）**：
  - `session/prompt` 参数 = `{ sessionId, prompt: [{type:"text",text}] }`（**非 ACP 标准的 message**，用 message 报 empty prompt）
  - 回答文本**必须从 `session/update` 通知的 `agent_message_chunk` 收集**（`update.sessionUpdate==="agent_message_chunk"` + `content.text` 拼接）
  - **transcript .jsonl 不实时更新**（persistAfterTurn 不写该文件）——勿从 transcript 读回答
  - 同会话多轮实测：上下文保持正常（第 2 轮"刚才结果+2"正确引用第 1 轮"1+1=2"）
  - `_reasonix.io/session/status_update` 事件：phase/usage/completion（usage 含 token/缓存，后续可采集）
  - reasonix 注入自身 system ~20k tokens（开销大，适合批量专用通道）
- 会话列表：Reasonix 存储于 %USERPROFILE%/AppData/Roaming/reasonix/sessions

## 验证

- 临时脚本已清理
