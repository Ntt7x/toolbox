## 二、feature：新闻中心数据工程能力（memo `mtee106b-kxkil4`）
需求：底层关键词精准/模糊匹配（非 LLM）→ 流式打标 → 标签处理（高亮词组/黑名单词组）→ 配置页接入。

**分层落地（契约先行）**
1. `packages/shared`：新增 `NewsMatchMode` / `NewsTagRule` / `NewsHighlightConfig` / `NewsBlacklistConfig` / `NewsTextConfig` / `NewsTextHit` / `ProcessedNewsItem` / `NewsRulesResult` / `NewsPreviewRequest|Result` / `NewsItemsResult`
2. `core/newsText.ts`（**新公共模块，纯函数 + 9 条单测**）：`normalizeText`（NFKC+小写+空白折叠，带下标映射保证命中区间回映原文）、`parseWordList`、`textSimilarity`、`findHits`（exact 整词边界 / fuzzy 滑动窗口+编辑距离，阈值 0.65，≤2 字词不允许编辑）、`matchText`
3. `features/newsCenter/textRules.ts`（**新业务编排**）：黑名单 → 打标 → 高亮流水线；`processNews`（逐条，分页/流式同一口径）、`processTextItem`（试跑）、配置读写 + `sanitizeTextConfig` 脏数据兜底；配置存 `settings:news.textConfig`，注册数据源
4. 路由：`GET/POST /tools/news/rules`、`POST /tools/news/preview`（试跑不落库）、`GET /tools/news/items` 改为返回加工结果（+ `blockedCount`）
5. 前端 `NewsCenterTool.tsx`：展示区渲染高亮 `<mark>` + 标签徽章 + 黑名单标记 + **标签筛选 chips** + 「已过滤 N 条」提示；配置区新增「🏷️ 文本加工配置」卡片（规则增删改启停、高亮词组、黑名单 + hide/mark、试跑预览）；原硬编码 `IMPORTANT_KEYWORDS` 上移为服务端默认规则 `builtin-important`

**关键设计**
- 词组输入用「草稿态 + blur/保存时解析」，避免受控输入吞掉逗号（前端经验 §6.2 同款陷阱）

## 教训（本次新发现）
- **调研类 memo 先核对已有能力再写结论**：微服务化调研推荐的 3 个工具 Toolbox 全有自研等价物——差点把「引入架构」当成「解决问题」
- **默认阈值先跑单测再定**：fuzzy 阈值原设 0.75 会让 3 字中文词（逆回购/美联储）永远无法容错（1/3 差异 = 0.667），改为 0.65 + 按长度分级允许编辑数
- **PowerShell 传中文/特殊字符给 node -e 会乱码**（`✖`、中文正文均被破坏）→ 临时验证脚本一律写成 `.mjs` 文件再执行
