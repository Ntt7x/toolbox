## 调研
- **Reasonix 源码**（main-v2）：`internal/agent/compact.go`——压缩触发 ratio（0.5 soft/0.8 compact/0.9 force）、**固定 tail 预算（16384 tokens）**、summaryTag 折叠、system 前缀稳定；`prune.go`——工具结果 snip（免费，可重新推导）；`internal/acp/status.go`——usage 事件结构（turn/cumulative 含 cacheHit/cacheMiss/cacheHitRatio/estimatedCost）
- **ACP 成熟实现**：官方 TS SDK `@agentclientprotocol/sdk` 模式——spawn + NDJSON 行切分 + mailbox 按 sessionId 路由、JSON-RPC error object、无自动重连（进程崩溃=重建单元）

## 实现
### chatSession.ts（模式 2，参考 compact.go）
- 压缩从"保留最近 6 轮"改为 **token 预算**：0.25 tok/char 估算（fallbackTokPerChar 同款）；6000 触发 / 4000 tail 预算 / 至少 2 轮
- 更早轮次机械折叠为 `[compacted 早期历史]` 标记（不调 LLM）；system 恒定前缀锚点永不删
- 每轮 ask 后自动检查压缩
- 实测：12 轮后 turns 12→9（自动折叠 4 轮，droppedTurns 统计）

### reasonix.ts（模式 3，参考 SDK mailbox + 状态管理）
- **会话注册表 KV 持久化**（`reasonixSession:<业务id>` → { reasonixSessionId, cwd, module, createdAt, lastAt, ttlMs }）——服务端重启/崩溃后恢复的基础；业务 API 改用注册表 id（createReasonixSession 返回业务 id）
- **多会话并发**：通知从单监听器改为 `promptListeners: Map<sessionId, listener>`（session/update + _reasonix.io/session/status_update 按 sessionId 分发）
- **崩溃恢复**：ACP 进程退出自动重建（pending 拒绝 + 下次调用 startAcp）；reasonix 侧会话丢失（unknown session）自动 `session/resume`（不重放历史）重试一次
- **usage 采集**：status_update 的 usage 事件（turn/cumulative 含 cacheHit/cacheMiss/estimatedCost）→ 记录到 llmUsage 统一监控（recordLlmUsage 从 llm.ts 导出）
- **实测**：1+1=2 → +3=5（usage 采集成功：prompt 41235 / cacheHit 20480 / cost 0.00297）→ **杀 ACP 进程后** ×2=10（崩溃恢复 + 上下文保持正确）✓

### 状态管理（stateful）总结
- chatSession（模式 2）：KV 持久化 + TTL 30 分钟 + 惰性过期清理（list 时）
- reasonix（模式 3）：注册表 KV 持久化 + TTL 30 分钟 + ACP 进程惰性单例崩溃重建 + session/resume 会话恢复
- 后续：可将注册表/会话列表暴露为 /api/llm/sessions 状态接口（待业务接入时做）
