## 改动
- **引擎六层**（`apps/server/src/core/data-infra/`）：
  - `queue.ts`：消息队列（enqueue/dequeue/ack，processing 状态、attempts 重投、TTL 过期、requeueStale 恢复、审计日志、peek、listQueues）
  - `taskRegistry.ts`：任务注册/执行/状态机（queued→running→done/failed→历史）、重试、外部任务登记（registerExternalTask）、并发防重
  - `scheduler.ts`：cron 调度（cron-parser）、missed 检测补跑、启动补跑
  - `derivator.ts`：源事件→衍生消息（taskDone/taskFailed 钩子、手动触发、运行记录）
  - `consumer.ts`：消息消费循环（幂等、失败重投、并发控制、统计）
  - `health`：健康检查聚合（任务失败/队列积压/孤儿/消费者未运行/派生失败/未标记 KV）
- **core/tasks 登记桥接**：createTask 传 module 自动登记 data-infra + 生命周期同步（tasks.test.ts 7/7 含登记模式 + after 兜底清理）
- **业务接入**：
  - tradeV2-snapshot（cron 任务 + 派生器 + 消费者全链路）
  - reverseRepo 调度 + 手动入口防并发
  - zhihuCrawler：令牌桶限速（zhihuRateLimit）+ 分级退避（40362→30min/403→5min/429→指数）+ 内容指纹去重 + 原子进度 + 完成派生消息 + 消费者
  - experiment ec/bmpi：setTimeout 手写调度 → cron 调度任务（语义修正：启动后 9h → 每日 09:00）
- **运管**：DataInfraTool 页面（任务/队列/派生器/消费者/健康卡片）
- **文档**：`domains/data-infra.md`（十章：架构/队列/任务/调度/派生器/消费者/运管/DDIA 对照/接入决策树/改造梳理）+ dev.md 引导
