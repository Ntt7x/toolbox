1. **反复重启真凶**：restartService 用 `cleanupPorts()` 无差别清两端口 → web 重启误杀
   server 的 tsx 子进程（server code=1）→ server 重启又杀 web → 互相踩踏无限循环
   → 改为只清当前服务端口 `killPort(port)`

   连续 3 次（15s）空闲才判异常；进程真退出立即重启；宽限期空闲计数归零
3. Start-Process `-ArgumentList` 传 JSON 字符串 → node 收到单参数 supervise 分支不匹配
   supervisor 立即退出 → 改逗号分隔独立参数
4. spawn(detached) 被 taskkill /T 按父链级联杀 → 改 Start-Process（powershell 退出后父链
   断开）；不能加 Redirect（powershell 挂起等句柄 → 工具超时杀父链又陪葬）
5. log() 同步追加 `.file/dev-logs/supervisor.log`（后台 stdout 丢弃也能排查重启原因）
6. 隐患：openSync logFd 从不关闭 → 重启多次 fd 泄漏 → 重启前 closeSync
7. 体验：start/restart 前台轮询两端口就绪（≤20s）打印 ✅；tsxCli 路径动态查找
   （写死 tsx@4.23.5 升级即失效 → 扫 node_modules/.pnpm/tsx@* 取最新）

验证（实测）：restart 一次成功+就绪提示；api/web 200 稳定；tsx 重编译不误重启；
kill server 自动重启且 web 不受影响；supervisor.log 仅一次启动记录。
