# 2026-09-03-02 — 仓位管理页首屏加载 15.8s → 0.8s（批量行情 + 有界并发 + 去重复请求）

**分支**：`perf/trade-v2-fast-load`（合并 main）
**会话主题**：修复「仓位管理 v2」打开页面加载数据过长的问题。用户选定方案：**只做性能修复，不引入成熟库、不动页面结构**。

## 一、问题定位（先量化再动手）

| 指标 | 值 |
|---|---|
| 首屏 `GET /api/tools/trade-v2`（冷缓存） | **15.8s**（prod 实测 24.3s） |
| 同接口（行情缓存热） | 152ms |
| 交易条目 / 去重标的代码 | 235 / **115** |
| 首屏逐代码行情请求次数 | **124 次** |
| 缺名条目 | 0（名称解析不是瓶颈） |

**根因（N+1 取数，非渲染瓶颈）**：
1. `latestPrices()` 对每个标的单独 `getQuoteSnapshot`（腾讯单只 → 东财 → 新浪三源 failover），115 只 ≈ 115 次网络往返；
2. 总览接口对 **每个分组**各调一次 `groupSummary` → 组内条目各派生一次、价格各取一次，组间标的重叠造成重复取数；
3. `getQuoteSnapshots` 逐代码降级是**串行 await** → 未命中代码的 RTT 串联叠加；
4. 行情 KV 缓存 TTL 5 分钟，过期后进页面必然重跑全链路；
5. 前端 `init` effect 与 `selectedId` effect **各触发一次分组分析请求**（首屏重复请求），且 overview → analysis 瀑布串行、无竞态保护。

## 二、修复（7 文件，+247 行，无新增依赖）

### 服务端
- **新增 `core/concurrency.ts`**：`mapLimit(items, limit, fn)` 有界并发映射（**保序**返回）+ `NET_CONCURRENCY = 8`。统一替代「无界 `Promise.all`」与「串行 await」两种极端。
- **`core/quote.ts` · `getQuoteSnapshots` 重写**：
  - **保序返回**（原实现先推缓存命中、后推未命中，顺序与入参不一致，调用方无法按下标配对）；
  - **批量结果落缓存**（原实现只缓存单源降级结果 → 批量命中的不写缓存，每次冷启都要重跑批量）；
  - **降级走有界并发**（原串行 await，N 只未命中 = N 次串联 RTT）；
  - 新增 `fetchTencentBatched`：单批上限 60 代码、批间并发 4。
- **`core/kline.ts` / `core/volatilityStore.ts`**：批量取数 `Promise.all` → `mapLimit`（无界并发会打爆行情源限流）。
- **`features/tradeV2/services.ts`**：
  - `latestPrices()` 由逐代码改为**一次批量快照**；
  - 名称缓存由「仅进程内」升级为「进程内 + KV 持久化（`tradeV2:name:`）」，冷启动不再为缺名条目发网络请求；
  - 新增 `listByGroupFrom(all, groupId)`；`groupSummary` 支持复用已加载条目与价格表。
- **`features/tradeV2/store.ts`**：抽出 `sortReplay` + `getGroupEntriesFrom(all, groupId)`，支持**一次读取、多组复用**（原每分组重读全量 KV 并排序）。
- **`features/tradeV2/index.ts`**：总览改为**一次读条目 + 一次批量行情**，再按组派生摘要。

### 前端（`TradeV2Tool.tsx`）
- 分组分析**唯一入口**：`analysisLoadedFor` 记录已加载分组，消除首屏重复请求（原 2 次 → 1 次）；
- `analysisSeq` 请求序号：切分组时**丢弃过期响应**，避免旧请求后到覆盖新分组数据；
- `analysisLoading` 独立加载态 + 顶部提示条：总览就绪后分组行与交易流水立即可用，分析稍后填充（渐进加载，不再整体白屏）。
