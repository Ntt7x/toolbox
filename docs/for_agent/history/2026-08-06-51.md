# 2026-08-06 51 · 服务端公共知识库模块（Reasonix ACP 承接 + /k 虚拟路径）

## 需求
用户提供分享对话（知识库架构：去 RAG，SQLite KV 精确存储 + LLM 提取内化/问答）并三点纠正：
1. **/k 移动到 .file/**（git 隔离）
2. **知识库是服务端公共功能模块**（非业务模块），不同业务可基于它实现特定业务知识库
3. **技术设计：Reasonix 承接知识库管理 + ACP 控制文件资源**（服务端精细控制）
4. 随后用户拍板：**本地网站不细控权限，直接给 Reasonix Agent 所有文件权限**

## 实现
### core/knowledge.ts（公共模块，位于 core 层）
- KV 前缀 `knowledge:`；条目 `{key, value, source?, updatedAt}`；key 分层点分隔校验（防穿越）
- CRUD：kbSet/kbGet/kbDelete/kbList(搜索)/kbSetMany/kbCount
- LLM 能力：kbImportFromChat（DeepSeek 分享 → LLM 提取事实 → 批量入库）、kbAsk（拆词检索 → 知识注入 → LLM 回答）
- **目录同步（Reasonix ACP 适配）**：KB_ROOT_DIR = `.file/k`（与 toolbox.db 同层，git 隔离）；kbSyncToDir（KV→文件，Agent 可读）、kbSyncFromDir（文件→KV，含 Agent 删除同步删）
- 数据源注册 `knowledge:`（本地数据管理可见）

### core/reasonix.ts（ACP 层）
- **/k 移到 .file/**：Agent 默认 cwd = DATA_DIR（.file），`/k/{key}` = `.file/k/{key}`
- 会话前 kbSyncToDir + fs.watch watcher（1s 防抖写回）
- **ACP 工具权限放开（用户拍板）**：createReasonixSession 后 `session/set_config_option tool_approval=yolo`（全自动批准，Agent 自由读写文件）——这是写入卡住的根因修复（默认 ask 模式等待 host 批准）
- handleToolCall（兜底）：tool_call(pending) → grant_permission 决策（文件类放行；bash/网络拒绝）
- request_permission 兜底：文件类放行，其余拒绝（保持安全底线）

### 移除业务层
- 删除 features/knowledge（HTTP 路由 + 任务接口）——知识库是 core 公共能力，不注册业务路由
- index.ts 装配层移除

## 排查过程（ACP 工具机制）
- write_file 卡 pending（phase=waiting_permission）：初判 host 需执行/回 tool_result → 试 host 执行、grant+tool_result 组合均卡
- 读 ACP.md 定位：host 未声明 fs 能力时 Reasonix 本地执行工具；**tool_approval 默认 ask** → 写操作要批准
- **根治：tool_approval=yolo**（配合用户"所有文件权限"决定）
