## 调研结论
- **Reasonix 二进制可用**：`npm i reasonix @reasonix/cli-win32-x64`（52MB，Windows amd64，v1.20.0）；`reasonix acp` 提供 ACP（NDJSON JSON-RPC 2.0 over stdio：initialize → session/new → session/prompt → close；会话独立 + persisted transcript；append-only 保前缀）
- **实测（--metrics）**：首次 prompt=20159 cache_hit=0 cost=$0.00285；`--continue` 续接会话第 2 轮 **cache_hit=20096（98.8%）** cost=$0.000216（**降 13.2x**）
- 配置：`reasonix setup` 或 `DEEPSEEK_API_KEY` 环境变量（与我们同机制）
- Reasonix 是完整 Go agent（非库），集成成本高（进程管理/ACP 客户端/其 20k tokens system 开销大），**适合做批量会话化专用通道，不宜全量替换**

## 会话层原型实测（短 system，模拟批量财报分析）
| 轮次 | A（append-only 会话） | B（独立调用） |
|---|---|---|
| 1 | prompt=61 hit=0 | prompt=61 hit=0 |
| 2 | prompt=167 hit=128（76.6%） | hit=0 |
| 3 | prompt=274 hit=128（46.7%） | hit=0 |
- 3 轮成本 A $0.000035 / B $0.000026——**短历史场景 A 未更便宜**（prompt 累积变长 + 单元化限制）
- **发现：DeepSeek 缓存按 ~128 token 固定间隔切单元，跨单元边界无法部分命中**（第 3 轮只命中第一个完整单元）
- **结论：append-only 会话是批量/长任务（历史 >> 新 query、system 大）专用优化**；我们页面单次分析（system 数百 tokens）主收益已由前缀稳定化获得；watchlist 一次分析 >5 只时可考虑会话化（方案 A 自研或方案 B ACP A/B 后再定）
