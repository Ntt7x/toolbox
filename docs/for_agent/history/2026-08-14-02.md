## 进程问题根治（用户专项）

- **根因**：① `dev start` 是前台常驻 supervisor——调用方（终端/工具进程）退出或被超时杀死时连带杀掉 tsx/vite 子进程；② tsx watch 源码变更重启时旧子进程端口未释放 → 新进程 EADDRINUSE 崩溃；③ supervisor 重启路径未先清端口、残留记录未清理。
- **修复**：
  - `dev.mjs`：start 改为 **detached 后台 supervisor**（`node dev.mjs supervise` 独立进程组常驻，`start` 立即返回）；stop 杀 supervisor 树 + 清端口；healthCheck 重启前强清端口 + 重试上限 8→12；新增 `cleanupSupervisorRecord` 清残留记录。
  - `apps/server/src/index.ts`：端口监听 EADDRINUSE 自动重试（1.5s×10，tsx watch 重启竞态自愈）。
  - 实测：start→health 200、触发 tsx watch 重启后仍 200、status 显示 supervisor 存活、stop 后端口全清。
