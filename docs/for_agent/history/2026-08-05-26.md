## 完成的功能

1. **布局重构（WatchlistTool）**：
   - 左栏紧凑化：新建区（名称+介绍）收窄、列表项密度提升
   - 新增 **Chat 导入区**（左栏）：链接输入 + 导入按钮 + 进行中状态
   - 右栏详情紧凑：标题行/介绍 textarea/添加行/表格间距收紧，理由列加宽、字号 0.78-0.8
2. **Chat 导入（服务端）**：
   - 提示词 `watchlist.import`（对话内容 → 专题名称/介绍/个股+理由，200 字介绍、6 位代码校验、
     排除项不收录、严禁编造）
   - `importFromChat(shareUrl)`：extractShare 提取对话（60k 字截断防超 token）→ LLM 整理 →
     robustJsonParse → 校验（6 位代码/名称/理由截断）→ createTopic + updateTopic 自动创建
   - 路由：POST /api/tools/watchlist/import（后台任务，10 分钟超时）+ import/task/:taskId 状态
3. 前端 api：watchlistImport / watchlistImportTaskStatus；导入轮询（120×3s）完成后自动选中新专题

## 关键教训

- **extractShare 返回 ShareExtractResult 对象**（{ok, messages}），不是数组——直接
  `Array.isArray(extractShare(url))` 会误判"提取为空"；需先判 ok 再取 .messages
- tsx watch 在 typecheck 报错期间不重启（旧代码继续跑），内存任务会因服务重启丢失——重发即可
